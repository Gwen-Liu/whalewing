# 界面评审

## 怎么查

1. 先读工程的界面规范、设计变量和组件约定；工程规范和下面的清单冲突时以工程为准。
2. 页面能渲染就先看实际效果：用宿主实际可用的浏览器工具打开，截图看层级、遮挡和间距，用键盘从头 Tab 一遍，看控制台有没有报错。有 Lighthouse 或 axe 时跑一次无障碍检查，用失败的节点定位到组件，不在整个仓库里盲搜。自动工具只能发现一部分问题，满分不等于合格。
3. 再按清单读代码。只报确实存在的问题，不为凑数报。
4. 修复后用同样的方法复查。

## 清单

**无障碍**

- 只有图标的按钮要有 `aria-label`；表单控件要有 `<label>` 或 `aria-label`，点标签能选中控件。
- 动作用 `<button>`，跳转用 `<a>`；不用加了点击事件的 `<div>`、`<span>`。
- 图片要有 `alt`，装饰图写 `alt=""`，装饰图标加 `aria-hidden="true"`。
- 标题层级连续；页面写明语言；异步提示（保存成功、校验错误）用 `aria-live="polite"`。
- 先用语义标签，不够再用 ARIA。
- 对比度：正文至少 4.5:1，大字（18px 以上或 14px 以上粗体）至少 3:1；焦点框和图形控件对背景至少 3:1。
- 可点目标至少 24×24 像素，触屏建议 44×44。
- 拖动、滑动、捏合等手势要有点击和键盘的替代方式。

**焦点**

- 所有可交互元素有清楚可见的焦点样式；去掉 `outline` 必须给替代。
- 用 `:focus-visible`；组合控件用 `:focus-within`。
- 固定头部、底栏和浮层不能挡住获得焦点的元素。弹窗打开时焦点进入弹窗，关闭后回到触发它的地方；不形成出不去的键盘陷阱。

**表单**

- 输入框设置正确的 `type`、`inputmode`、`autocomplete` 和有意义的 `name`。
- 不禁止粘贴。
- 提交按钮在请求开始前保持可用，请求中显示进行中；错误显示在对应字段旁，提交失败后焦点移到第一个错误。
- 有未保存的内容时，离开页面要提醒。

**动效**

- 遵守系统的“减少动态效果”设置；只对 `transform` 和 `opacity` 做动画；不写 `transition: all`。
- 动画能被用户操作打断；自动播放超过 5 秒的动效要能暂停。

**排版与内容**

- 省略号用“…”，加载文案以“…”结尾；中文正文用中文标点。
- 数字列和需要对比的数字用等宽数字（`font-variant-numeric: tabular-nums`）。
- 长文本、长单词不撑破容器（截断、换行，弹性子项加 `min-width: 0`）；空字符串、空列表不显示成坏掉的界面。按短、中、超长三种内容各想一遍。
- 图片写明宽高，避免加载时页面跳动；首屏以外的图片懒加载。

**状态与导航**

- 空状态、加载中、失败、无权限都有对应界面，失败时说明怎么办。
- 删除等不可撤销的操作要先确认，或者提供撤销。
- 工程有此约定时，筛选、分页、当前标签页等状态能用链接还原。
- 链接支持在新标签页打开。

**性能**

- 超过约 50 项的长列表考虑虚拟滚动或 `content-visibility: auto`。
- 渲染过程中不读布局（`getBoundingClientRect`、`offsetHeight` 等），读和写分批进行。

**深色模式与本地化**

- 深色主题设置 `color-scheme`；原生下拉框显式设置前景色和背景色。
- 日期、数字、金额用 `Intl` 格式化，不写死格式。

**文案**

- 按钮写具体动作（“保存修改”，不写“确定”“提交”）；同一个动作在按钮、提示和结果里用同一个词。
- 错误信息说清发生了什么、怎么解决。
- 用用户的说法，不用内部术语。

**看到就报的写法**：用 `user-scalable=no` 或 `maximum-scale=1` 禁止缩放、禁止粘贴、`transition: all`、去掉焦点框不给替代、可点的 `div`、没有尺寸的图片、没有标签的输入框、没有名字的图标按钮、写死的日期和数字格式、只能用手势完成的操作。

## 结果

按文件分组，每条一行：`文件:行 - 问题`，修法不明显时补半句。检查过没问题的文件写“通过”。分开写清：实际打开看过的范围、只读了代码的范围、没检查的范围（例如没有用读屏软件实测）。

## 退出

交付问题清单和检查范围。作者自查不替代独立检查；问题由界面作者修改，评审者不代改。完成本次检查即退出。
